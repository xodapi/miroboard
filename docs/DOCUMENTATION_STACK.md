# Стек документации и лицензии

Решение от 2026-09-23. Документация остаётся обычным Markdown в этом репозитории.
Специализированные генераторы не подключаем. В собранный продукт — `dist/index.html`
и крейт `board-core` — не попадает ничего, кроме MIT и Apache-2.0.

## Когда специализированный стек имел бы смысл

| Требование | Стек | Есть ли оно у MiroBoard |
|---|---|---|
| Несколько репозиториев, версии документации рядом с версиями продукта | AsciiDoc + Antora | Нет. Один репозиторий, учебник уже лежит в `docs/tutorial/`. |
| Печатная вёрстка: формулы, колонки, PDF как основной артефакт | Typst | Нет. Артефакт — интерактивная доска, не книга. |
| Жёсткая схема контента: неизвестный тег — ошибка сборки | Markdoc | Нет для сайта. Схема процесса уже проверяется в Rust (`validate_bpmn`), схема файла — в TypeScript. |
| Чертёж как код, который надо издавать отдельно от редактора | Typst или AsciiDoc + диаграммы | Нет. Чертёж — это сама доска. Обмен с другими инструментами уже делает BPMN XML. |

Пока ни одной из этих четырёх причин нет, второй язык разметки только раздваивает правки.

## Лицензии, если когда-нибудь понадобится генератор

Коммерческое использование само по себе разрешено у всех четырёх. «Без проблем»
для MIT-продукта — более узкое условие: зависимость не должна заражать
`dist/index.html` и не должна тащить чужой веб-сервис.

| Инструмент | Лицензия | Коммерция | Почему не берём сейчас |
|---|---|---|---|
| Asciidoctor | MIT | Да, без условий сверх сохранения копирайта | Второй язык разметки без выигрыша. |
| Antora | MPL-2.0 | Да, но изменённые файлы Antora нужно публиковать под MPL | Слабый копилефт. Как внешний генератор сайта не заражает Markdown, но в бандл его класть нельзя. Мультирепозиторности у нас нет. |
| Компилятор Typst, крейт `typst` | Apache-2.0 | Да. При распространении изменённого компилятора нужен файл `NOTICE` | Веб-приложение typst.app — отдельный проприетарный продукт, на него опираться нельзя. Компилятор в WASM раздует единственный HTML и не нужен доске. |
| Markdoc | MIT | Да | Ещё одна Node-схема поверх уже существующих типов. |

`mdBook` (Rust, MPL-2.0) — тот же класс, что Antora: годится как внешняя утилита,
не годится как зависимость крейта, который уезжает в браузер. GitHub и так
показывает текущий Markdown. Отдельный генератор книги не добавляем.

## Что берём из Rust

Не новый генератор документации, а то, что уже держит домен и остаётся
пермиссивным:

- `serde` / `serde_json` — MIT OR Apache-2.0. Граница WASM — JSON, без сети.
- `quick-xml` — MIT. Это и есть diagram-as-code: импорт и экспорт BPMN 2.0 XML
  с BPMN-DI. Отдельный CAD-язык не нужен.
- `wasm-bindgen` — MIT OR Apache-2.0.
- `rustdoc` — часть rustc, MIT OR Apache-2.0. Документация крейта живёт в
  `///` над публичными функциями `wasm/board-core`. Отдельный сайт для неё не
  собираем: публичный контракт для браузера — это шесть `#[wasm_bindgen]`
  функций, их и так вызывает TypeScript.

Новый крейт в `wasm/board-core` допустим только если он MIT, Apache-2.0 или
«MIT OR Apache-2.0», не тянет сеть и не нужен лишь ради документации.
GPL, AGPL, MPL, SSPL, BUSL и проприетарные SDK в этот крейт не входят:
они либо обяжут публиковать исходники сборки, либо запретят коммерческий
бандл. То же правило для `dependencies` в `package.json` — они вшиваются
в `dist/index.html`. Dev-зависимости в файл не попадают, но копилефт туда
тоже не кладём, чтобы случайный импорт не утащил его в бандл.
