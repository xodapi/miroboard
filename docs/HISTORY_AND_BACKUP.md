# История и резервные копии

## Источник истины

- Git-репозиторий и основная ветка `main` на GitHub являются общей историей проекта.
- Коммит создаётся только после проверки изменения. Автоматические commit, pull или push запрещены.
- Перед публикацией нужно просмотреть `git diff`, запустить подходящие проверки и явно выполнить
  `git push`.

## Локальная история с Jujutsu

`jj` настроен в co-located режиме поверх того же Git-репозитория. Он не заменяет GitHub и не
создаёт отдельную историю.

```powershell
jj status     # изменения рабочей копии
jj log        # история изменений
jj op log     # журнал операций jj
jj undo       # отменить последнюю операцию jj
```

Для совместимости в Windows настройки репозитория должны оставаться такими:

```powershell
git config --local core.autocrlf input
jj config set --repo working-copy.eol-conversion none
```

Не используйте `git clean -xdf`, пока нужен локальный журнал jj, эта команда удаляет `.jj/`.

## Резервные копии

Для независимых зашифрованных снимков рабочего каталога подходит `rustic`. Его следует настроить
только после выбора владельцем проекта отдельного хранилища и способа управления ключом.

Минимальные требования:

1. Хранилище находится вне рабочего компьютера и вне папки репозитория.
2. Снимки зашифрованы, ключ не хранится рядом с репозиторием.
3. В backup включаются исходники, `docs/` и необходимые конфигурации, но не `node_modules/`,
   `dist/`, `.git/` и `.jj/`.
4. Восстановление из снимка периодически проверяется в отдельную временную папку.

Резервная копия дополняет Git и jj, но не заменяет их.
