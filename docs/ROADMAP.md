# Долгосрочная программа развития

## Готово

- BPMN-редактор, XML import/export и BPMN-DI;
- deterministic token runner, XOR/AND, Monte Carlo и распределения длительности;
- стоимость, роли, capacity, utilisation и очередь ресурсов;
- защита BPMN-семантики: неподдерживаемые inclusive gateways и неявные
  развилки отклоняются валидацией, а не дают тихо неверный расчёт;
- BPMN round-trip сохраняет условия, default-flow, вероятности XOR-потоков
  и параметры симуляции задач;
- автономная single-file сборка и учебные BPMN-примеры.

## Ближайшие этапы

1. Рабочий календарь ресурсов, SLA и deadline-анализ. Уже в симуляции.
2. Полноценная очередь: приоритеты, FIFO и несколько экземпляров процесса. Уже в симуляции: политика роли, классы поступления и общий пул слотов.
3. Bottleneck, cost и what-if аналитика. Первый срез есть: Парето-фронтир мощности против времени цикла в панели симуляции. Стоимость как вторая ось — нет: она часто падает вместе с ожиданием и не показывает лишних людей.
4. ARIS/eEPC/VACD и mind-map поверх общего графового ядра.
5. Process mining import и сверка модели с event log.

## Принципы

GitHub хранит опубликованную историю. Git и jj обеспечивают локальную историю и
undo. Rust/WASM содержит детерминированную доменную логику, React — интерфейс.
Новые функции сначала получают учебный fixture и тест. Документация остаётся
Markdown в этом репозитории: Antora, Typst и Markdoc не подключаем, пока нет
мультирепозиторности, печатной вёрстки или схемного сайта. Лицензионное правило
и уже используемые крейты — в [`DOCUMENTATION_STACK.md`](./DOCUMENTATION_STACK.md).

## Решение: без живой совместной работы

Живой мультиплеер — курсоры, relay, ключи, приглашения — **не делаем**.
Продукт остаётся офлайн: один HTML-файл, логика в Rust/WASM, ноль сети и без
новых зависимостей. Конкурируем владением файла, детерминизмом симуляции и
историей внутри документа, а не плавностью чужих курсоров.

Анализ в `COLLABORATION_ANALYSIS.md` остаётся как исследование, почему текущая
CRDT-схема непригодна для слияния. Это не план реализации.

Офлайн-срез холста: поиск по доске (Ctrl+F) со списком совпадений, умные
направляющие при перетаскивании и при изменении размера, группы (Ctrl+G),
блокировка объекта (не сдвигается, не меняет размер и не поворачивается),
раздельные заливка и обводка (прямоугольник и круг; стикер — только заливка,
узел BPMN — только обводка), память настроек интерфейса на устройстве.
Календарь ресурсов, SLA, очередь и Парето-фронтир узкой роли уже в симуляции.
Дальше по холсту — не равные интервалы и не фреймы. Следующая быстрая победа
холста — стиль стрелки (пунктир и наконечник), не пипетка и не стоимость на
фронтире.

## Production hardening

- Публичные Yjs signaling-серверы удалены в Phase 1. Свой транспорт взамен
  **не вводим**: живая сессия вне продукта (решение выше);
- разделить большой UI-компонент (`src/App.tsx`, 2534 строки) и добавить browser-level
  тесты для Simulation;
- сохранять Git history в UI через build-time generated manifest, а не вручную;
- зафиксировать в CI бюджеты: размер `dist/index.html`, размер `.mboard` после
  N правок, fps на доске из 500 узлов;
- привести `ACHIEVEMENTS.md` в соответствие с кодом (Canvas 2D → SVG, Zustand не
  используется, «MessagePack-like» → JSON, размер бандла 2.1 МБ → 1.1 МБ).
